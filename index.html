Meridian — Forensic RAG Measurement Framework

May 2026

A two-layer forensic measurement framework for retrieval-augmented generation. Layer 1 is a deterministic span-overlap taxonomy — no LLM in the loop — that scores retrieval against human-annotated character offsets across four legal corpora (~79M characters, ~800 evaluation queries). Layer 2 is a separate LLM-judged layer for answer correctness and groundedness, isolated so a metric shift is never confused with a pipeline change. The measurement layer is the contribution; the retrieval pipeline is the proving ground.

What it proves
A deterministic measurement anchor rigorous enough to catch its own bugs — and isolated from the pipeline so you always know what moved and why. The two-layer separation means a metric change is never confused with a pipeline improvement. The deterministic Layer 1 can be run against an external published baseline to verify the ruler itself, not just the system it measures.
Key findings
  • Retrieval Precision@1 2–20× the published ZeroEntropy baseline, 3 of 4 corpora calibrated within a ~2–3pp drift floor — full optimized system vs. their dense-only baseline
  • Answer accuracy lifted from 26% to 75% on contracts; +7.9pp average across four corpora after tuning the retrieval config
  • Four silent measurement bugs caught before shipping — a model-ID alias routing every "Pro" run to the cheaper model, a (0,0)-span default zeroing all retrieval metrics, a channel mismatch, and a chunk-size confound — each surfaced by verify-before-trust checks the layer separation made possible
  • Retrieval stack transferred zero-shot to NFCorpus (3,633 medical IR documents), beating classic BEIR baselines at nDCG@10 0.399
Stack
Python · Qdrant · voyage-4-large · BM25 · hybrid retrieval · convex-combination fusion · document routing + LLM selector · deterministic span-overlap taxonomy · DeepSeek (synthesis) · Langfuse · LegalBench-RAG (ContractNLI, CUAD, MAUD, PrivacyQA)

Aether — LLM Workflow Engine

Apr 2026

A reason-act-observe agent for financial documents. Give it a fund statement, P&L CSV, or compliance PDF and a plain-language goal — it queries the data with SQL, builds a grounded visualization, and delivers an answer where every value traces back to a source cell. Or refuses, honestly, when the document can't support the question.

What it proves
A reasoning agent for financial documents that stays honest. Output is grounded in computed SQL results — every value traces to a source cell — and the engine refuses to fabricate when the evidence isn't there, returning a partial result with the reason why. Full observability: every reasoning step, tool call, and observation is written to a SQLite trace.
Key findings
  • 75.5% end-to-end on FinQA (n=200); retrieval R@5 0.85, MRR@3 0.73
  • Adversarial stress test: asked for a five-year chart from a two-year document — refused to invent the missing years, returning a partial result with evidence
  • Generalization demonstrated on finance, legal, and medical documents with no code changes — only the domain prompts differ
  • Full observability: every step, tool call, and observation traced to SQLite and surfaced in a Streamlit trace explorer
Stack
Python · reason-act-observe loop (direct SDK, no LangChain) · BM25 + all-MiniLM-L6-v2 dense · ChromaDB · RRF + flashrank cross-encoder · DuckDB · Camelot (PDF tables) · Vega-Lite (grounded charts) · Pydantic v2 · SQLite trace · gpt-5.4-mini (provider-swappable)

Production RAG Stack Forensics

Extends the polymarket autopsy methodology to the stack AI engineering teams actually ship on, with a custom MCP server exposing the instrumentation as agent-queryable tools.

What it proves
Forensic methodology generalizes from a trading system I built to the production AI stack companies hire for — industry-standard tools throughout, with measurement-driven analysis of where the abstractions help and where they get in the way. The sharpest finding was in the measurement itself: an evaluation bug that nearly shipped a wrong conclusion.
Key findings

  • Custom MCP server exposes eval results, retrieval latency, failure-mode breakdown, and per-stage cost as agent-queryable tools

Polymarket Trading Bot Autopsy

What it proves
Forensic methodology applied to a real production system — from data pipeline, to LLM-driven analysis, to live execution, to public technical writeup. Built the system, ran it, broke it, documented why.
Key findings
  • Paper PnL inflated ~135× by three measurement bug classes — reversing real-world performance rankings

Aegis — Verifiable RL Environment for Defensive Cybersecurity IN PROGRESS

2026

A reinforcement-learning environment where an AI agent learns to find and fix real software vulnerabilities — scored by a multi-signal deterministic verifier engineered to resist reward hacking. The verifier is the contribution, not the agent. Extends Meridian's forensic measurement discipline from retrieval metrics to RL reward integrity.

What it's building
A training environment where an RL agent patches real vulnerabilities in sandboxed repositories, scored by a deterministic verifier with orthogonal signals that each close a named reward-hack class — feature deletion, test tampering, patching the literal payload while leaving the technique live. The verifier is evaluated like a classifier against a labeled gold set of genuine fixes and deliberately gamed solutions, so "my verifier catches reward hacking" is a claim with a number behind it, not an assertion.
Planned evaluation
  • Agent capability against ZeroDayBench (anti-memorization CVE-porting), SecureAgentBench, and CyberSecEval
  • Verifier integrity: precision/recall on hack detection against a labeled gold set of genuine fixes vs. reward-hacked patches — the Meridian forensic discipline applied to RL rewards
  • RLVR run: does reward-hacking rise as the policy is trained against the verifier? Does capability improvement come with reward-gaming improvement?
How it extends Meridian
Meridian asked: does the retrieval metric mean what you think it means? Aegis asks the same question about an RL reward signal. The verifier is scored against an external labeled ground truth — the same verification discipline — now applied to a training objective rather than a retrieval benchmark.
Planned stack
Python · Docker (sandboxed patch execution) · pytest-style harness · CodeQL / Semgrep (static analysis signal) · TRL or verl (RLVR training loop) · PyRIT / Garak (attack tooling) · ZeroDayBench · SecureAgentBench · CyberSecEval
